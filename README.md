# Food — Flutter Food Ordering App

A food ordering mobile app built with Flutter and Firebase, covering the full user journey from browsing products to tracking an order in real time.

## 📱 Project Overview	

Food is an e-commerce style mobile app that lets users browse food categories and products, manage a cart and wishlist, check out with a saved delivery address, and track their orders. It also includes a lightweight admin view for merchants to manage incoming orders. The app is fully localized in Arabic (RTL) using `flutter_localizations`.

## ✨ Features

**Authentication**
- Email/password login and registration via Firebase Auth
- Forgot password flow
- User profile linked to Firestore with a `role` field (`user` / `admin`)

**Products & Search**
- Browse categories and featured products (Firestore)
- Product details screen
- Real-time search using Firestore prefix queries

**Cart & Wishlist**
- Add/update/remove cart items, synced live via Firestore streams
- Wishlist with real-time sync

**Checkout & Orders**
- Address management (multiple addresses, default address)
- Checkout flow with payment method selection
- Order history synced in real time
- Order details screen

**Admin**
- Order management screen visible only to users with `role: admin`, with order status updates

**UI/UX**
- Full Arabic RTL support
- Skeleton loading (shimmer) instead of plain spinners
- Reusable Empty State / Error State widgets
- Custom image handler with graceful fallback for network/asset images

> Some UI (payment methods screen, notifications screen, search filters, settings toggles) exists but is not yet functionally wired up — see **Future Improvements** below.

## 🏗️ Architecture

The project follows a **feature-based structure**, with each feature split into `data`, `domain`, and `presentation` layers:

- `data/` — Repositories that talk directly to Firebase
- `domain/` — Plain Dart models (e.g. `UserModel`, `ProductModel`)
- `presentation/` — Cubits, screens, and widgets

State management is handled consistently with **flutter_bloc (Cubit)** across every feature. Navigation is manual, using `Navigator.push` with `MaterialPageRoute` (no named routes or routing package).

## 🔥 Firebase Integration

- **Firebase Auth** — email/password sign-up, sign-in, and password reset.
- **Cloud Firestore** — primary database:
  - `users/{userId}` — profile data, with subcollections `cart`, `wishlist`, `addresses`
  - `categories` — product categories
  - `products` — product catalog
  - `orders` — all placed orders, queried by `userId` for users and unfiltered for admin
- **Firebase Storage** — stores profile pictures at `users/{userId}/profile.jpg`.

## 🎨 UI/UX

The UI is built fully in Arabic with RTL layout support, using Google Fonts' Cairo typeface for readability. Loading states use shimmer-based skeleton placeholders instead of plain spinners, and empty/error states are handled through shared, reusable widgets for a consistent experience across screens.

## 🚀 Getting Started

### Prerequisites
- Flutter SDK (`^3.12.2` or compatible)
- A Firebase project with Auth, Firestore, and Storage enabled
- FlutterFire CLI configured for your own Firebase project

### Installation
```bash
git clone https://github.com/<your-username>/<repo-name>.git
cd food
flutter pub get
```

### Firebase Configuration
This repo intentionally does **not** include `lib/firebase_options.dart` or platform Firebase config files (they contain project-specific keys). To run the project:
```bash
flutterfire configure
```
This regenerates `firebase_options.dart` and the platform config files linked to your own Firebase project.

### Run
```bash
flutter run
```

🔮 Future Improvements & Project Status
This project is currently an initial/demo version developed to demonstrate the core functionality, UI/UX, Flutter architecture, and Firebase integration.
The following features are planned for future development and would be added when the project is expanded into a real-world, production-ready application:
•	Payment Gateway: Integration with a real payment gateway for secure online payments.
•	Advanced Search & Filters: Fully functional filtering by price range, rating, and other criteria.
•	Push Notifications: Real-time push notifications using Firebase Cloud Messaging (FCM).
•	Unified Error Handling: A centralized error and failure-handling layer for a more robust user experience.
•	Localization: Full multilingual support, including Arabic and English.
•	Testing: Comprehensive unit, widget, and integration tests to improve reliability and maintainability.
•	Query Optimization: Optimizing Firestore queries and moving filtering operations from the client side to Firestore where appropriate for better performance and scalability.
Note: These features are not considered missing core functionality in the current version. They represent future enhancements that would be implemented as part of developing the project into a complete, production-ready application.
